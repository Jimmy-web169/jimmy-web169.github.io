六月我寫過 [AgentDeck](/zh/2026/06/17/agentdeck/)：一個跑在自己電腦上的小 dashboard，把 Claude Code 和 Codex 默默寫在硬碟裡的對話記錄視覺化出來，資料不會離開你的機器。

這三個月我每天都在用它，也慢慢累積出一堆「這裡好煩」。同時開三、四個專案的時候，在 agent 的切換上感覺沒有很順暢；想找上禮拜某一段對話，要點好幾層；最尷尬的是 CLI 廠商偷偷改了記錄格式，我是幾天後看到畫面壞掉才發現。

這次 2.0 的更新，我想針對以下幾點一項項優化。

![tour](https://static.jimmyblog.site/2026-09-08-agentdeck-2/tour.gif)

（影片版和功能細節放在 [jimmyblog.site/AgentDeck](https://jimmyblog.site/AgentDeck/)，這篇想聊的是我為什麼做這些。）

## 像開瀏覽器分頁一樣切換 agent

最大的改變是介面變成 Chrome 那種分頁。每一段對話就是一個分頁，不管它是 Claude Code、Codex 還是 Antigravity 的，也不管在哪個資料夾。切 agent、切專案，就跟切網頁一樣。

按 ⌘K（Windows 是 Ctrl+K）可以直接搜任何一段對話。記不得名字沒關係，它會把每段對話的第一句話列出來，通常看一眼就想起來了。

![home](https://static.jimmyblog.site/2026-09-08-agentdeck-2/home-activity.webp)

同一個 repo 常常會同時有 Claude Code 和 Codex 的對話，所以我希望建立類似 workspace 和 pinned 的機制，讓自己可以依近期的工作狀態去活用：相關的對話收成一個 workspace，正在忙的專案就 pin 起來。

![sidebar](https://static.jimmyblog.site/2026-09-08-agentdeck-2/sidebar-workspaces-pinned.webp)

## Google Antigravity 也進來了

這次新增了 Google 的 `agy` CLI，成為第三個 provider，畫面跟另外兩家一樣。

![antigravity](https://static.jimmyblog.site/2026-09-08-agentdeck-2/session-antigravity.webp)

## Insights：我想看看自己是怎麼用 AI 的

這個功能是從一個小疑問開始的。我每天跟 agent 工作，但其實說不出自己「怎麼」用它：是早上比較常開，還是晚上？一段對話通常聊多久就結束？哪些專案開了頭就丟著？Stats 只會告訴我花了多少 token，回答不了這些。

所以我做了 Insights，想要有一點觀測自己使用 AI 狀況的感覺。它看的是過去 30 天有幾天在用、通常幾點用、一段對話平均聊多久、哪些專案已經很久沒碰。做完自己看了一輪，才發現我幾乎都在早上跟 agent 工作，而且禮拜二最忙。

![insights](https://static.jimmyblog.site/2026-09-08-agentdeck-2/insights.webp)

## 叫 agent 幫我寫它自己的設定

用了幾個月的 coding agent 之後，我察覺到一件事：幫各家 provider 填 config，其實會花掉滿多時間。每家的規範都有點不一樣，同一個東西叫法不同、放的位置不同、能做的事也不同。每次要加個 hook、接個 MCP server，都得先去翻文件、確認格式，真正動手反而是最快的部分。

那既然 agent 自己最懂自己的設定，為什麼不讓它來？現在在設定頁直接用白話說你要什麼，比方「幫我把這個專案設定好」，AgentDeck 會開那個 CLI 自己的終端機，把你的需求、現在的設定檔和官方文件一起交給它。

![handoff](https://static.jimmyblog.site/2026-09-08-agentdeck-2/config-handoff.webp)

## 讀懂每一家的格式，不該是監控工具的全部工作

這是我這次花最多時間想的一件事。

最近開始看到 [ACP](https://agentclientprotocol.com/get-started/introduction)、[agent-plugins.org](https://agent-plugins.org/) 這類統一協定出現，我也意識到，coding agent 同樣需要一個統一的協議層，去描述它們到底在我們電腦上記錄了什麼。Codex 寫在 `~/.codex`、Claude Code 寫在 `~/.claude`、Gemini 寫在 `~/.gemini`，本質上都是用 jsonl 或 SQLite 在記對話，但格式各自為政。這正是 AgentDeck 想做一個統一監控介面時最大的難點：每加一家就要重新讀懂一套格式，而且它們隨時會變。

這次我先從自己做得到的部分開始：把每一家「記錄長什麼樣」寫成 YAML，連同版本一起記下來。

我希望未來能慢慢促成一份協議的產生，讓監控這件事不再那麼困難，不需要處理那麼多資料格式的差異。這份 YAML 就是第一步。

另一個影響我的是 DeepSeek 最近的 harness。它把整個 harness 拆成一個個可以替換的模組，這個概念我很喜歡。AgentDeck 這次也往這個方向走：每個 provider 就是一個獨立的模組，核心不認識任何一家廠商。接下來我希望把更多 component 都做成這樣，慢慢走向插件化，讓有興趣的開發者可以只寫自己在意的那一塊，不用先讀懂整個專案。
