三個月前我寫了 [AgentDeck](/zh/2026/06/17/agentdeck/)：一個跑在本機、只讀 CLI 自己寫在硬碟上的檔案、資料不外傳的 dashboard，用來看 Claude Code 和 Codex 到底在做什麼。

這三個月我自己每天用，也越用越清楚哪裡卡：同時開三四個專案時，一個 provider 一個畫面很快就不夠；想找上週那段對話要點好幾層；CLI 廠商默默改了記錄格式，我是幾天後看到畫面壞掉才知道。所以 2.0 幾乎是重寫。九件事：

![tour](https://static.jimmyblog.site/2026-09-08-agentdeck-2/tour.gif)

（影片版和一頁式介紹在 [jimmyblog.site/AgentDeck](https://jimmyblog.site/AgentDeck/)。）

## 1. 第三個 provider：Google Antigravity

`agy` 加進來了，跟 Claude Code、Codex 用同一套畫面：對話、sub-agent、Raw、Stats、Artifacts、Config。它的記錄格式沒有公開，對話在 `transcript_full.jsonl`，workspace、模型、token 藏在 SQLite 的 protobuf blob 裡，我把欄位一個一個對出來（對照它自己 `/usage` 的輸出）。加一個 provider 的成本，現在是 `server/providers/` 底下一個資料夾加一份 YAML descriptor。

![antigravity](https://static.jimmyblog.site/2026-09-08-agentdeck-2/session-antigravity.webp)

## 2. 像瀏覽器一樣瀏覽

Chrome 式的分頁列，橫跨 provider 和追蹤的資料夾。每段對話是一個分頁、有自己的深連結，分頁會記住位置、可以拖曳排序、重開瀏覽器還在。切換三個 agent 和十幾個專案，就像切網頁。

![home](https://static.jimmyblog.site/2026-09-08-agentdeck-2/home-activity.webp)

## 3. Workspace 和 pin

一條側欄管所有東西：彩色的資料夾 chip、把同一個 repo 在不同 provider / 資料夾底下的對話收成一個 **workspace**（同一個資料夾出現在好幾處時會自動建議）、把手上正在做的 **pin** 起來。pin 或分組是「搬走」那一列，所以同一個東西不會出現兩次。

![sidebar](https://static.jimmyblog.site/2026-09-08-agentdeck-2/sidebar-workspaces-pinned.webp)

## 4. Midnight 主題

新的冷色系深色主題，跟預設的 Graphite、亮色的 Paper 並列。主題只是 token 覆寫，所以 provider 和 workspace 的顏色在每個主題下亮度都對。

## 5. Preferences

主題、密度、provider 和狀態點的顏色（任何 hex、色相飽和度滑桿、自己存的色票）、專案路徑顯示幾層、首頁清單多長、側欄顯示哪些區塊。每一組旁邊一個 (i)，一句話說明，不塞說明文字。

![preferences](https://static.jimmyblog.site/2026-09-08-agentdeck-2/preferences-open.webp)

## 6. 快捷鍵和快速切換

⌘/Ctrl+K 模糊搜尋任何 provider、任何資料夾裡的專案和對話；→ 進到專案看它的對話（標題加第一句 prompt，記不得名字也找得到）；Enter 開、⌘/Ctrl+Enter 開新分頁。Alt+T / W / [ ] / 1…9 操作分頁。完整清單在分頁列的 ?，修飾鍵會依你的 OS 顯示。

![switcher](https://static.jimmyblog.site/2026-09-08-agentdeck-2/quick-switcher-open.webp)

## 7. Insights

這頁講的是「你」怎麼跟 agent 工作，不是花了多少 token：過去 30 天活躍幾天、連續幾天、一天哪個時段、一週哪天、一段對話多長、幾個 prompt、哪些專案已經很久沒碰。token 和工具統計留在 Stats。

![insights](https://static.jimmyblog.site/2026-09-08-agentdeck-2/insights.webp)

## 8. AI 功能

**Ask the agent**：在任何 Config 頁（或 Insights）用自己的話說想要什麼，AgentDeck 會開該 provider 自己的終端機，帶一份 brief 進去：你的需求、那個檔案和它現在的內容、對應的官方文件，還有這個 CLI 有哪些「積木」（instructions、commands、rules、output styles、workflows、skills、sub-agents、hooks、MCP、plugins）。brief 要求 CLI **先訪談再動手**：逐一解釋、一次問一題、用內建的 find-skills 去 skills 生態系找現成的、列出計畫、你點頭才改。AgentDeck 自己不呼叫任何模型、不改任何檔案。

![handoff](https://static.jimmyblog.site/2026-09-08-agentdeck-2/config-handoff.webp)

## 9. Provider 協議，加上格式漂移偵測

這是我最想做的一件事。現在每家 CLI 都在 `~/.claude`、`~/.codex`、`~/.gemini` 寫自己的格式，沒有共同規範。AgentDeck 的 `spec/` 定了一份每個 provider 都要實作的契約：session、sub-agent（`children[]`）、tool call、token、memory、MCP、history、stats 用同一套詞彙；每個 CLI 一份 YAML descriptor；一個 conformance gate（fixture 加 golden 輸出）。

然後是 **format probe**：每次啟動讀每個追蹤資料夾最新的記錄，跟 descriptor 比對。新的 record type、少了必要欄位、型別變了，當天就在那個資料夾的 chip 上掛一個標記，細節在 Folders 對話框。這週它就抓到 Claude Code 2.1.263 和 codex 0.153 各自新增的幾個型別。

![folders](https://static.jimmyblog.site/2026-09-08-agentdeck-2/folders-dialog.webp)

## 順帶一提

三家的 Stats 現在是同一個畫面，共同欄位在前、各家專屬的標註出來；`make all` 會先把三個 CLI 都更新；demo 素材全部從一個合成的假資料根產生，所以 repo 裡沒有任何人的真實對話；CI 在 ubuntu / windows / macos 三個 OS 跑測試、build、spec 和隱私掃描。

還是那句：如果你也每天跟 AI coding agent 一起工作，歡迎來玩、給個 star，或是照 `spec/` 加一個新的 provider 送 PR。
