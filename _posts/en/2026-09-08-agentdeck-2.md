Back in June I wrote about [AgentDeck](/en/2026/06/17/agentdeck/): a small dashboard that runs on your own machine and shows you the conversations Claude Code and Codex quietly write to disk. Nothing leaves your computer.

I've used it every single day since, and the annoyances piled up. With three or four projects open, switching between agents never felt smooth. Finding a conversation from last week took too many clicks. And the embarrassing one: a CLI vendor quietly changed its file format, and I only noticed days later when a screen broke.

In this 2.0 update I wanted to work through these points one at a time.

![tour](https://static.jimmyblog.site/2026-09-08-agentdeck-2/tour.gif)

(The video and the feature details are at [jimmyblog.site/AgentDeck](https://jimmyblog.site/AgentDeck/). This post is about why I built them.)

## Switch agents like browser tabs

The biggest change: the UI is now Chrome-style tabs. Every conversation is a tab, whether it's Claude Code, Codex or Antigravity, whatever folder it lives in. Switching agents or projects feels like switching web pages.

Hit ⌘K (Ctrl+K on Windows) to search any conversation. Can't remember the name? It shows the first thing you said in each one, and that's usually enough.

![home](https://static.jimmyblog.site/2026-09-08-agentdeck-2/home-activity.webp)

The same repo often has both Claude Code and Codex conversations, so I wanted something like workspaces and pins that I could shape around whatever I'm working on that week: related conversations go into a workspace, and the project I'm busy with gets pinned.

![sidebar](https://static.jimmyblog.site/2026-09-08-agentdeck-2/sidebar-workspaces-pinned.webp)

## Insights: I wanted to see how I actually use AI

This one started from a small question. I work with agents every day, but I couldn't really say *how*: do I reach for them in the morning or at night? How long does a conversation usually run before I stop? Which projects did I start and then abandon? Stats only tells me how many tokens I spent, and that doesn't answer any of it.

So I built Insights, mostly to get a feel for my own AI habits. It looks at how many of the last 30 days I used an agent, what time of day, how long a session runs on average, and which projects have gone quiet. The first time I read mine, I learned that I do almost all of it in the morning, and Tuesdays are the busiest.

![insights](https://static.jimmyblog.site/2026-09-08-agentdeck-2/insights.webp)

## Let the agent write its own config

After a few months of living with coding agents, one thing stood out: filling in each provider's config eats a surprising amount of time. Every vendor has slightly different rules. The same idea has a different name, lives in a different place, does slightly different things. Every time I wanted to add a hook or wire up an MCP server, I'd start by reading docs and double-checking the format; the actual edit was the quick part.

The agent understands its own config better than I do, so why not let it do the work? Now you type what you want on the settings page, in plain words, like "set this project up for me", and AgentDeck opens that CLI's own terminal and hands it your request, the current config file and the official docs.

![handoff](https://static.jimmyblog.site/2026-09-08-agentdeck-2/config-handoff.webp)

## Reading every vendor's format shouldn't be the whole job

This is the part I spent the most time thinking about.

Lately we've started to see unifying protocols like [ACP](https://agentclientprotocol.com/get-started/introduction) and [agent-plugins.org](https://agent-plugins.org/), and it made me realise coding agents need the same thing for what they record on our machines. Codex writes to `~/.codex`, Claude Code to `~/.claude`, Gemini to `~/.gemini`. Underneath, they're all keeping conversations in JSONL or SQLite, but every format is its own thing. That's exactly what makes a unified monitoring UI hard: every new vendor means learning a new format from scratch, and any of them can change at any time.

So this release starts with the part I can do myself: writing down what each vendor's records look like in YAML, versions included.

Longer term I'd love to see this grow into an actual protocol, so monitoring stops being hard and nobody has to juggle this many data formats. The YAML is step one.

The other thing that shaped this release is [deepseek-harness](https://github.com/deepseek-ai/deepseek-harness), DeepSeek's open-source agent framework. Its motto is "Everything is a Plugin": the whole harness is split into modules you can swap out, and I liked that idea a lot. AgentDeck now leans the same way: each provider is a self-contained module, and the core doesn't know any vendor by name. Next I'd like to push more of the components in that direction, towards proper plugins, so a developer who cares about one piece can build just that piece without reading the whole project first.
